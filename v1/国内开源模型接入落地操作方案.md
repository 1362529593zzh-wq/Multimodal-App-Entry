# 国内开源模型接入落地操作方案

## 1. 我对本次改造要求的理解

你的目标不是单独新增一个模型服务页面，也不是只把工作台 UI 调整成预览图，而是打通一条完整链路：

1. 在模型配置服务中维护中国国内开源大模型或国内模型网关。
2. 模型服务按厂商集中管理，可以新增、编辑、启停、删除和测试连接。
3. 模型服务通过能力绑定，决定工作台的图像生成、图像识别、文生语音、文生 PPT、文生视频分别能调用哪些模型。
4. 工作台打开能力参数区时，模型候选和参数 schema 来自后端配置，不再主要依赖前端 mock。
5. 工作台提交任务时，可以显式传入模型服务编码；如果不传，则后端按能力绑定表选择默认模型。

UI 目标按你给出的预览图执行：

- 模型服务配置页：左侧厂商筛选，中间服务卡片列表，新增和编辑使用居中弹窗。
- 工作台页：左侧会话管理，中间消息流，底部固定输入区，点击能力后在同一输入区展开参数。

## 2. 建议你实际操作的顺序

### 第一步：先完成模型配置底座

先做数据库和后端，而不是先堆前端页面。

需要完成：

- 扩展 `app.mm_model_service`，增加厂商、协议类型、脱敏密钥、自定义请求模板、排序字段。
- 保留 `app.mm_function_model_binding` 作为能力与模型服务的绑定主表。
- 保留 `app.mm_param_template` 作为工作台参数 schema 的来源。

原因：

- 只有先把模型服务变成“注册中心”，后面的工作台才知道应该调用哪个国内模型。
- 否则前端即使做成截图样式，也只能维护一堆无法被工作台稳定消费的数据。

### 第二步：录入或导入国内模型服务

每个模型服务至少需要整理这些信息：

- `serviceCode`：服务编码，例如 `qwen-image-prod`
- `serviceName`：页面显示名，例如 `通义万相图像生成`
- `vendorCode`：厂商编码，例如 `qwen`
- `vendorName`：厂商名称，例如 `通义千问`
- `modelCode`：模型标识，例如 `wanx2.1-t2i-turbo`
- `modelName`：模型名称
- `modelType`：模型类型，例如 `image`、`vision`、`audio`、`ppt`、`video`、`text`
- `functionCode`：默认能力归属，例如 `image_generation`
- `providerType`：调用协议，第一阶段建议用 `openai_compatible`、`ollama`、`custom_http`
- `endpoint`：接口地址
- `authType`：鉴权方式，例如 `none`、`bearer`、`api_key`
- `supportedOptions`：工作台参数候选，例如比例、风格、模板
- `extraConfig`：厂商扩展信息，例如 region、responseMode、apiPath

### 第三步：配置能力绑定

一个模型服务要被工作台调用，必须进入 `app.mm_function_model_binding`。

例如：

- `image_generation` 绑定 `qwen-image-prod`
- `image_recognition` 绑定 `glm-vision-prod`
- `text_to_speech` 绑定 `cosyvoice-prod`

绑定规则：

- 同一个能力可以绑定多个模型。
- 每个能力建议只有一个启用中的默认模型。
- 工作台优先使用用户选择的服务；没有选择时使用默认绑定。

### 第四步：配置工作台参数 schema

如果某个模型有专属参数，写入 `app.mm_param_template`：

- `templateType` 推荐使用 `composer_schema`
- `templatePayload` 存输入区 schema
- `presetParams` 存默认参数

第一阶段如果没有 schema，也可以先只依赖 `supportedOptions` 自动生成基础参数栏。

### 第五步：工作台调用

工作台提交时建议携带：

- `capability`：能力编码
- `serviceCode`：模型服务编码，可选
- `options` 或 `composerOptions`：参数
- `sourceAssetIds`：参考图、上传图片等素材

后端选择模型的顺序：

1. 优先使用前端传入的 `serviceCode`
2. 查能力绑定表中的默认服务
3. 查能力绑定表中排序靠前的启用服务
4. 兜底使用功能配置中的 `defaultServiceCode`
5. 最后才使用旧的 `functionCode` 匹配模型服务

## 3. 当前这一轮建议先做到的代码范围

为了快速形成可联调闭环，本轮优先完成：

- 新增数据库迁移脚本，扩展模型服务字段。
- 后端模型服务支持厂商字段、协议字段、删除、厂商字典、测试连接。
- 工作台后端选模型优先走能力绑定表。
- 工作台 schema 支持按 `serviceCode` 获取。
- 前端模型服务页改成预览图方向：厂商筛选、卡片列表、居中弹窗。

暂不在第一轮强行完成：

- 完整 provider 适配器拆分。
- 密钥加密存储表。
- 批量导入接口的复杂校验。
- 工作台附件上传和多模型真实调用的全部协议差异。

这些适合等你整理好真实国内模型配置后，再做第二轮。

## 4. 国内模型配置 JSON 示例

```json
{
  "serviceCode": "qwen-image-prod",
  "serviceName": "通义万相图像生成",
  "vendorCode": "qwen",
  "vendorName": "通义千问",
  "vendorType": "official",
  "modelCode": "wanx2.1-t2i-turbo",
  "modelName": "Wanx 2.1 Turbo",
  "modelType": "image",
  "functionCode": "image_generation",
  "providerType": "openai_compatible",
  "endpoint": "https://your-gateway.example.com/v1/images/generations",
  "authType": "bearer",
  "timeoutMs": 60000,
  "enabled": true,
  "publishStatus": "PUBLISHED",
  "isDefault": true,
  "allowFrontSelect": true,
  "supportedOptions": {
    "ratio": ["1:1", "4:3", "16:9"],
    "style": ["清新", "写实", "海报", "电商"]
  },
  "extraConfig": {
    "region": "cn",
    "responseMode": "url"
  },
  "remark": "国内文生图主模型"
}
```

## 5. 验收方式

模型服务配置页：

- 可以按厂商筛选。
- 可以新增、编辑、启停、删除服务。
- 卡片展示服务、模型、接口、状态、认证方式、模型类型。
- 新增和编辑是居中弹窗，不再是表格页。

工作台：

- 能力参数区展示模型服务候选。
- 选择模型后提交任务，后端保存对应 `serviceCode`。
- 不选择模型时，后端能按绑定表找到默认模型。
- 后续替换真实国内模型 endpoint 后，工作台无需重写页面结构。
